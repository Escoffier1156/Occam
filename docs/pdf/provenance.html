2. 機構 A：有界メモリの処理機構（最も「技術的効果」の形をしている）

何か

ストリーム処理で、作業メモリがデータ量から独立することを型と所有権で強制する構造。

// engine/src/main.rs [LOCK]
for bulk in &mut bulks {
    let bulk = bulk?;
    let mut op = DomainOperator::new(pass, args.learning_rate);
    carry = op.absorb(&bulk, carry);
    // op and bulk are dropped here, before the next iteration
}

3つの不変条件で成立している。

内容実装箇所
1バルクを同時に2つ持たない。読み手は返したバルクへの参照を保持せず、先読みしないbulk.rs [LOCK]×2
2オペレータ間を生き延びるのは carry だけで、そのサイズはコンパイル時固定（[Candidate; K]、[f32; W]、[[u32; BINS]; 2]）carry.rs [LOCK]
3演算器とバルクを同時に1つしか持たない。次の反復の前に drop されるmain.rs [LOCK]、process.rs [LOCK]

実測

D軸（バルク固定、データ量 62倍）ピーク RSS +2.59%
B軸（データ量固定、バルク 256倍）固定費 34 MiB が一定
1万倍−2.7%（データ/RSS = 73倍、2048次元・実データ・100万件）
代償AUC −0.0001

主張できそうな形

「有界メモリであること」ではない（それは公知の性質）。**それを静的に強制し、

破れたら検出する機構**の方。

所有権と drop 順で不変条件を型レベルに落とす構成

AST ロック（KeepOut）で不変条件を守るコード領域を機械的に封じる。整形・コメント・

変数改名は無視し、構造変更だけを拒否する

テストが不変条件そのものを検査する（2軸、因子を環境変数で振る）

製品経路にいる（2026-10-12 に訂正）

py/screenable.py の rankability() が engine/target-fp/release/engine を

subprocess で起動し、順位付けの可否を判定している。エンジンは製品の一部。

前日の棚卸しで「製品は呼ばない」と書いたのは、文字列検索の誤り（パス結合で書かれていて

engine/target という文字列が現れない）。

特許の相談としては、こちらの方が強い。使われていない機構ではなく、製品が通る経路の

機構である。

弱点

ストリーム処理で有界メモリ、は一般的な設計。「強制する」部分が差分

[LOCK] コメント ＋ AST ハッシュという方式自体に類例があるか、私は調べていない

言語機能（Rust の所有権）に依存した主張は、言語を変えると成立しない

3. 機構 B：実行前に要求を拒否する検問機構（構成として最も特徴的）

何か

スクリーニング要求を、1分子も読む前に、公表規則との整合で止める機構。

検査内容実装
スライス矛盾要求が「イオン化可能窒素」を含み、ライブラリが pH 7.4 中性と予測されるスライスなら停止。公表データ（陽性12/41 対 中性0/39）を根拠として出すprovenance.py
障壁不一致条件がグラム陰性外膜の規則で、ライブラリが血液脳関門を測っているなら停止occam.py + knobs.APPLIES_TO
語彙外を丸めないMW 500 は 450 に寄せず停止。登録値を列挙して返すoccam.py NUMERIC
別の量への読み替えを拒否「電荷」は引退した knob。スライス選択に黙って回さず停止occam.py CHARGE_WORDS
事実の主張を破棄入力中の件数・AUC・骨格数は要求ではないので捨て、理由付きで一覧occam.py FACT_CLAIMS
標的の不在ラベルが存在しない標的は cannot be answered ＋ 実測の代替案feasible.py + screenable.py
スコープ不一致第1パスと第2パスが違う量を読んでいたら停止propose.py
不可能な計数骨格数 > 生存数 なら落ちるpropose.py

主張できそうな形

**「要求と、参照する公表規則と、データの出自を突き合わせ、実行前に矛盾を検出して

停止する」という構成。個々の検査ではなく、検問所として閉じていること。**

弱点

入力検証そのものは普遍的。「公表規則との照合」が差分だが、規則は他人のもの

自然言語処理を使わない決定的照合（閉じた語彙）は、むしろ単純な実装

ビジネスメソッド寄りに見られる可能性（法域による）

4. 機構 C：出自型付きの緩和と frontier（重み付きスコアを使わない）

何か

各設定に出自の型を持たせ、緩和の提案を型で制約する。

published    公表規則が既に言っている範囲内の置換（新しい化学的主張をしない）
relaxation   数値閾値を動かしただけ（主張が元から無い）
unjustified  新しい化学的主張。提案してはならない

そのうえで、重み付きスコアで1つに決めず、条件を満たす仕様を全部返す。

score = w1×生存 + w2×多様性 − w3×penalty   ← 使わない

理由：w は発明物で、「最良」が重みの産物になる。順序は

（緩和ステップ数、出自、決定的タイブレーク）の辞書式のみ。

主張できそうな形

**「提案の各要素に出自の型を付け、型が許す範囲でのみ緩和を生成し、

単一解ではなく充足解の集合を返す」**構成。監査が1行で済むこと（論文が言っているか、

数字を動かしただけか）が効果。

弱点

多目的最適化で Pareto frontier を返すのは公知

「出自を記録する」はデータ来歴（provenance）の一般論

組み合わせが差分だが、進歩性があるかは私には判断できない

5. 機構 D：拒否を測定要件に変換する機構

何か

適用範囲外という判定を、測定すべき化合物数に変換する。

適用範囲の検定   各化合物に閾値内の訓練近傍があるか
       ↓ 同じ閾値で
クラスタリング   近傍を持たない領域 = 1クラスタ
       ↓
出力             クラスタ数 = 測るべき化合物数、被覆曲線、閾値感度

実測例：307件が範囲外 → 268件測れば全被覆、115件で半分。

主張できそうな形

「適用範囲判定の閾値と同じ閾値でクラスタリングし、クラスタ数を測定要件として返す」

という変換。拒否で終わらず、拒否を解消する実験計画の規模を出す。

弱点

クラスタリングによる代表化合物選定（diverse subset selection）は創薬で極めて一般的

適用範囲の判定も標準

「同じ閾値を使う」という結び方が差分だが、自明と見られる可能性が高い

私の見立てでは、A〜D のうちこれが一番弱い。ただし現場価値は一番高い。

6. 機構 E：対照付きの判定

何か

重い判定（適用範囲外、inert）に、同じ測定を訓練集合内で回した対照を必ず添える。

predicting activity: can be answered only by extrapolating
  median 0.212 against a 0.4 threshold
  positive control: passes
    the same measurement run inside the training set gives median 0.747,
    with 94.0% at or above the threshold
    this rules out: a fingerprint radius or bit-length mismatch, or salts
    and stereochemistry left on one side

理由：out_of_domain と「計算が壊れている」は同じ顔をする（禁忌79）。

主張できそうな形

「判定の出力に、同一の計算経路を既知陽性集合に適用した結果を強制的に併記する」機構。

弱点

陽性対照は実験科学の基本。計算に持ち込んだだけ、と見られる

ただし「強制」（対照なしでは出力しない）が構成要素になるかは弁理士の判断

7. 使う前に知っておくべきこと

1. KeepOut は Apache-2.0 で、このリポジトリと同じ著者・同じライセンス。

third_party/keepout/ に vendor してある

2. ZINC22 の開放世代のみを使用（data/raw/zinc22/manifest.json に記録）。

再配布には書面許可が要るので、このリポジトリは SMILES を同梱せず、

tranche 名と取得手順だけを持つ

3. eNTRy は Hergenrother ラボの公表成果。適用しているのであって競合ではない

4. 外部検証がゼロ。他人が一度も回していない

5. 実験を一度もしていない。細胞に触っていない
