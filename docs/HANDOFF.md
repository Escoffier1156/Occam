## 0. 現在地（まずここ）

### これは何か

**研究者のアシストをする検問所。**創薬候補のリストを出す道具ではない。

```
プロンプト入力 → ビッグデータをバルク処理でその都度対応 → アシスト出力
```

出すのは3つ。

| | 内容 |
|---|---|
| **成立する** | この仕様はこのデータで答えられる。緩和は何ステップ必要か |
| **成立しない** | 答えられない。何が欠けているか |
| **代替案** | **実測から**。証拠が持つ分解能、床を越える仕様、最も近い訓練集合 |

**分子は出力しない。**どれを作るかは専門家の判断。

### 責任の境界（商品の文言としてもこれ）

```
❌ 「我々が測り、あなたが判断する」
✅ 「渡すものの整合性は我々の責任。科学的判断はあなたの責任」
```

科学的な正しさの証明は求められていない。**ただし渡したものが要求どおりであることは
保証する。**2026-10-09 と -10 に、この保証が3回破れた（§12、§13）。

### 使い方

```bash
occam "256 distinct scaffolds from the cationic ZINC library,
       primary amine, rotatable bonds at most 5,
       molecular weight strictly under 450"

occam --spec request.json    # 記録・提出用。こちらが正
```

書き方と注意点は **`docs/prompt_format.md`**（実装から転記）。

## 1. Occam とは（機構。§0 のプロダクトを支えるもの）

**§0 を先に読むこと。**ここに書いてあるのは**機構**で、プロダクトではない。

大規模データを固定サイズのバルクに区切り、バルクごとに一時的な演算器を生成して処理し、**結果だけを次に引き継いで演算器とバルクを破棄する**演算機構。これをバルクの数だけ繰り返す。

### 機構とプロダクトの関係（ここが噛み合っている）

固定メモリの強みは**任意規模を安く掃けること**で、それが得意なのは：

- 100万件全部に性質を計算して分布を出す
- ライブラリの何割が訓練範囲の内側かを数える
- **K 個の仕様を1パスで同時に評価する**（`sweep.py`：27仕様。**224 KB 固定は 54仕様で測った値**）

**全部「実行可能性と被覆率の問い」で、予測の問いではない。**だから機構の強みは
アシスト役に写り、弱点（訓練データ）が候補生成を縛る。配置として自然。

予測の質は訓練データで上限が決まる。そこが弱点（129件、0.6%、標的分解なし）。

狙いは作業メモリをデータ量から独立させること。`M ≈ D / N + R`（D=データ総量、N=バルク数、R=引き継ぎ結果のサイズ）。

元は「Molt」という名前で、2026-10-07 に Occam へ改名した。

### この registry は1つの障壁についてのもの（2026-10-11）

`knobs.py` の設定は全部 eNTRy 則で、**グラム陰性外膜への侵入**についてのもの。
一般的な透過性の規則ではないし、他の障壁の規則でもない。

**それが `APPLIES_TO` に記録されるまで、どこにも書いていなかった。**だから血液脳関門の
データ（B3DB、7,805件）に eNTRy 条件を向けても、最後まで走って何も異常を報告しなかった。
**電荷スライスの取り違えと同じ沈黙が、別の場所にあった。**

| ライブラリ | 障壁 |
|---|---|
| ZINC（-N / -O / -P） | **なし。**カタログなので何も測っていない＝矛盾しない |
| IMI-COMBINE / CHAMP / GramNegAccum | グラム陰性外膜 |
| **B3DB** | **血液脳関門** |

不一致なら理由を出して停止する（`--yes` で承知のうえ実行は可能）。
**`LIBRARY_BARRIER` に書かれていないライブラリは「不明」として扱い、registry と一致すると
仮定しない。**`tests/test_request.py` が、命名可能な全ライブラリに障壁の記録があることを
固定しているので、**次にライブラリを足すときに障壁を書かないと落ちる。**

#### BBB の knob は作っていない

数字付きの公表ルールがこのリポジトリに記録されていない。作れば全設定が `relaxation` か
`unjustified` になり、**「published か、閾値を動かしただけか」で1行で監査できるという
registry の性質が崩れる。**禁忌70（文献に閾値が無いことがある）と同じ理由。

答えられるのは **BBB についての問い**（この集合は B3DB の適用範囲内か、何件測れば入るか）で、
**BBB を eNTRy 条件で screening することではない。**

#### 測ると、分かることがある

ZINC -O を eNTRy 2条件で絞った集合の、測定済み集合への最近傍（中央値）:

```
IMI-COMBINE (activity, 22,051)         0.212
B3DB (blood-brain barrier, 7,805)      0.202   ← 2位
CHAMP (permeability, 1,132)            0.168
GramNegAccum (permeability, 197)       0.141
```

**グラム陰性の規則で絞った集合が、グラム陰性の実測集合より BBB の実測集合に近い。**
どれも閾値 0.4 に届かないので判定は変わらないが、**どのデータが足りないかの読み方が変わる。**
障壁を併記したから読める形になった。

### 絶対に守る不変条件（3つ）

1. **R はバルクサイズにもデータ量にも依存しない固定長。** `Carry` に `Vec` や `HashMap` を入れてはいけない
2. **ピークメモリが D に比例して増えない**
3. **同時に存在する演算器とバルクは1つ。** 先読みもバッファリングもしない

**この3つを壊す変更は、速度が上がっても却下。** ただし「1パスで学習する」は不変条件ではない（メモリの話であってI/O回数の話ではない）。多エポックは可。

### 不変条件は KeepOut で機械的に守られている

**KeepOut は `third_party/keepout/` に同梱してある**（2026-10-11）。それまでは
`shell.nix` が `/home/shogo/KeepOut/src` という絶対パスを指していて、**他のどのマシンでも
ガードが不在になり、ロック検査が自分を skip していた。**skip は pass と同じ顔をする。

| | |
|---|---|
| 上流 | `https://github.com/Escoffier1156/KeepOut.git` commit `ee9ac0a` |
| 記録 | `third_party/keepout/manifest.json`（commit・3ファイルの SHA256） |
| 乖離の検出 | `tests/test_invariants_locked.py` がハッシュを照合。manifest を直さずにコピーを変えると落ちる |
| 不在の扱い | **skip ではなく失敗**（`test_the_guard_is_not_silently_absent`） |

> **ライセンスが未宣言。**上流に LICENSE が無いので、**この束を外部に渡す前に上流で
> ライセンスを決めて manifest に記録する必要がある。**公開リポジトリでも、宣言が無ければ
> 受け取った側に許諾が無い。Docker/ZIP を渡す段の前提条件。


`/home/shogo/KeepOut`（ユーザー自作、MIT）。`# [LOCK]` / `// [LOCK]` でコードを囲み、構造変更を拒否する。整形・コメント・変数名の変更は無視。

9箇所をロック済み（`keepout.json`）。`tests/test_invariants_locked.py` がテスト一式に組み込み済みで、
- ロック領域の構造変更
- `keepout.json` からのロック削除

の両方を検出する。`keepout init` を再実行するとロックを消した状態でハッシュが再生成されるので、テスト側に「存在すべき9つのロック」を理由付きで固定してある。

ロックを追加したら `keepout init .` で登録し、**既存ロックのハッシュが変わっていないことを差分で確認**してから `REQUIRED_LOCKS` に追記する。未登録のロックは `check` が警告を出すが、保護はされていない。

呼び出しは `PYTHONPATH=/home/shogo/KeepOut/src python3 -m keepout.cli check .`。`shell.nix` に `KEEPOUT_SRC` を定義済み。

### カバレッジ（`py/coverage.py`、基準は実行前に宣言）

評価プール 11,025件（真のヒット 3,037件 = 27.55%）に対して、公開透過データが何割を語れるか。

| 領域 | box | neighbour | **covered** | covered のヒット率 | 全ヒットの何割 |
|---|---|---|---|---|---|
| CHAMP（755件） | 6.2% | 1.1% | **0.6%** | 5.88%（4件） | 0.1% |
| GramNegAccum（129件） | 37.3% | 28.6% | **22.7%** | 45.59% | 37.6% |
| union | 38.1% | — | **23.1%** | 44.87% | 37.6% |

- **box** = 全記述子が訓練側の1〜99パーセンタイル範囲内。**必要条件にすぎない**
- **neighbour** = 標準化記述子空間での最寄り訓練点までの距離が、訓練セット内部の最近傍距離分布の p95 以下
- **covered** = 両方。これが見出しの数字

**最近傍基準に変えると CHAMP は 6.2% → 0.6%（10分の1）。** 箱だけを報告していたのが誤りだった。

**ただし最近傍基準にしても「答えられる割合」にはならない。**箱が厳しすぎる方向に誤っていたので、より厳しい基準に変えても解釈の問題は解決しない。`py/answerable.py` が直接検定した結果、membership は AUC を予測しない。

二つの含意：

1. **訓練件数ではなく化学的な近さが効く。** GramNegAccum は129件で 22.7% を覆い、CHAMP は755件で 0.6%。ライブラリが抗菌薬なので、抗菌薬で作られた GramNegAccum の方が近い
2. **CHAMP の適用範囲内はヒット率が全体を下回る**（5.88% 対 27.55%）。ただし68件中4件なので数字として弱い

範囲外の内訳（禁忌23）：CHAMP は MW が 83.0%、芳香環 51.5%、HBA 44.6% で外れる。GramNegAccum は logP 36.7%、回転結合 29.0%、芳香環 25.2%。

### 箱の外は「答えられない」ではない（`py/answerable.py`、2026-10-09）

**カバレッジの数字を「モデルが語れる割合」として読むことは支持されない。**同じモデル・同じ重みで、評価集合を covered / uncovered に分け、**差のブートストラップ CI** を出した（2群は互いに素なので差が素直に出る。最初は2つの CI の重なりで判定していたが、それは禁忌44 そのものなので差し替えた → 禁忌54）。

16方向のうち測定できたのは12方向（covered が1件以下の4方向は測定不能）。

| 判定 | 方向数 |
|---|---|
| 差の CI が 0 を含む | **9** |
| 差の CI が 0 未満（uncovered が有意に良い） | **3** |
| **差の CI が 0 超（covered が良い）** | **0** |

**covered が有意に良い方向は1つも無い。**差の CI 幅は 0.054 〜 0.214 なので、分解能は ±0.03 〜 ±0.11。

### ただし「外でも大丈夫」とは読めない（難易度が交絡している）

単一記述子で達成できる最良 AUC を難易度の代理指標として両側で測ると：

| | 結果 |
|---|---|
| uncovered の方が易しい方向 | **11 / 12** |
| rho(難易度ギャップ, 差) | **−0.510** |
| **OPPOSITE の3方向のギャップ** | **+0.1050 / +0.0887 / +0.0848 = 全体の上位3つ** |

**「uncovered が有意に良い」3方向は、難易度ギャップが最大の3方向と完全に一致する。**つまり「箱の外の方が予測しやすい」は difficulty で説明され、**membership の効果ではない。**

箱の外はたいてい分布の端で、端は単一記述子でも分かれる。**記述子の箱で切ると、切った側が系統的に易しくなる。**これは分割の性質であってモデルの性質ではない。

### この検定が establish すること（ここまでに限る）

AUC は評価した集合の中での順位統計で、covered と uncovered は**ラベルの散らばり方が違う別の判別問題**なので、2つの AUC は同じ尺度の上に無い。示せるのは：

> **内外という分割は、モデルの順位付けが悪くなる部分集合を特定しない。**

カバレッジの割合を「答えられる割合」として読むことを拒否するにはこれで足りる（その読みには外側が悪いことが必要）。**逆に「適用範囲外でも大丈夫」とは読めない**（禁忌55）。しかも難易度の交絡は membership 効果を**覆い隠す向き**に働いている（uncovered が易しいので uncovered の AUC が上がる）。

**留保：** これは**順位付け**（AUC）の検定。箱の外で確率の校正が崩れている可能性は残る。スクリーニング用途では順位が効くのでこの指標が適切だが、校正は別途（禁忌53）。

**§4 への帰結：** 0.6% / 22.7% / 23.1% は**距離の記述として有効、能力の上限としては書けない。**§4 の主力は検出力の議論に移す。
