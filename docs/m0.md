## 仕様の変更

### 1. エンジン入力は「1パート = 1行グループ」のパートディレクトリ
- 形式：`<name>_x<n>/part-00000000.parquet, part-00000001.parquet, …`。各パートは行グループ 1 つ（8,192 行以下）。
- エンジンは行グループを 2 つ以上持つ parquet ファイルをエラーで拒否する。
- 理由：parquet のフッタは行グループ数に比例する。行グループの大きさを固定すると D に比例し、不変条件 2 を破る（実測で x100 のフッタは 136 KB、RSS は +10.2%）。
- 帰結：外部の parquet（標準的なライターは複数の行グループを書く）は、すべて `py/gen_scale.py` などで分割してから渡す。
- **未決（M2 までに決める）**：これを恒久的な仕様とするか、エンジン側でフッタを分割して読む実装に置き換えるか。

### 2. BulkReader はパートを自分で開閉する
parquet クレート（v60）の `RowIter` は、次の行グループを開いて先頭ページを読んでから旧リーダーを捨てる。切り替えの瞬間に 2 行グループ分のページが共存し、不変条件 3 を破る。そのため BulkReader は、旧パートを drop してから次のパートを開く。

### 3. glibc の mmap 閾値を 64 KiB に固定
`mallopt(M_MMAP_THRESHOLD, 64 KiB)`。固定しないと glibc が閾値を動的に引き上げ、drop したバルクがヒープ上で断片化する。その結果、ピーク RSS が実行ごとに最大 +19% 揺れた（D には比例しない）。

### 4. ピーク RSS の計測方法
Python から `wait4` で取る `ru_maxrss` は使えない。subprocess は vfork で起動するので、exec 前の Python 自身（約 40 MB）が子の最大値に入る。そこでエンジンが報告する VmHWM（exec でリセットされる）と GNU `time` の `%M` を取り、大きい方で判定する。両者は一致している。
また「100倍のデータ量 ≥ ピーク RSS の 10 倍」をテストで要求し、計測が壊れていれば検出できるようにした。

### 5. ingest は RFC 4180 準拠
- TSV も引用符を解釈する。改行を含むフィールドは 1 レコードとして復元する。
- 落とす対象：パース後の列数不一致（width）、`--required` に指定した列が空（required、既定では指定なし）、UTF-8 不正（utf8）、引用符の不正（parse）、空行（blank）。標準出力に理由別の件数を出す。
- `tests/test_ingest.py`：区切り文字・引用符・改行を含むランダムな表で往復させる property test。
